# Design

## Context

Снимок профайлера (`ProfilerCapture`) уже ходит в Play Mode: фаза в `SessionState`, `[InitializeOnLoad]` после
перезагрузки домена, сэмпл раз в кадр из `Application.onBeforeRender` и `EditorApplication.update`, счётчики
`UnityStats` и `FrameTimingManager`, прерывание при выходе из Play Mode и перекомпиляции. Точки и их файл, вкладка
«Точки обзора» — из `add-viewpoints`. API этапа (`XRStats.TryGetGPUTimeLastFrame`, `TryGetDroppedFrameCount`,
`XRDevice.refreshRate`, `Transform.RotateAround`, `EditorApplication.EnterPlaymode/ExitPlaymode`) собраны пробной
компиляцией против DLL 2019.4.41f2 24.10.2026.

## Goals / Non-Goals

**Goals:**
- Настоящее время кадра в 30 худших местах уровня за 2–3 минуты, одной кнопкой.
- Ничего не менять в сцене на диске.

**Non-Goals:**
- Сборка и замер Development Build — итоговые цифры остаются за профайлером на сборке.
- Маршрут «прогулкой» между точками и запись видео.
- Управление трекингом шлема (отключение позиционного трекинга) — шлем лежит, rig двигается.

## Decisions

- **Свой класс `ViewpointTour`, общий сэмплер с `ProfilerCapture`.** Фазы замера другие (точка → направление →
  разогрев → сбор), но сэмпл кадра тот же; накопитель (суммы, минимум, пик dt, CPU, GPU, счётчики `UnityStats`)
  выносится в `FrameSampler`, и `ProfilerCapture` переходит на него без изменения своих чисел (тест снимка
  профайлера остаётся зелёным).
- **Фазы:** `Idle` → `EnteringPlay` → `Settle` (30 кадров: скрипты игры создают rig и игрока) → по каждой точке и
  направлению `Move` → `Warmup` → `Collect` → `Finish`. В `SessionState`: фаза, список id точек, номер точки и
  направления, параметры. Перезагрузка домена бывает только при входе в Play Mode; перекомпиляция посреди замера —
  прерывание, как у профайлера.
- **Результаты по ходу — в `SessionState` после каждого направления** (JSON накопленного), в файл точек — при `Finish` и
  при прерывании. Так прерванный замер не теряет измеренное, а файл не пишется каждые полсекунды.
- **Rig:** VR-камера — включённая Camera с Target Eye ≠ None и без Target Texture; двигается `transform.root`
  её объекта. Поворот: `RotateAround(голова, вверх, нужный азимут − текущий азимут головы)`, сдвиг: `точка −
  голова`. Наклон и высоту головы трекинг не меняет — шлем лежит. Альтернатива — двигать саму камеру: трекинг
  перезаписывает её позу каждый кадр.
- **Заморозка:** у двигаемого объекта и его детей Rigidbody → `isKinematic`, CharacterController → `enabled =
  false`; прежние значения запоминаются и возвращаются в конце, если замер начат в Play Mode (иначе выход из Play
  Mode вернёт всё сам). Кого двигать, ищется и морозится на первом `Move` — после `Settle`, когда rig уже создан.
- **Итог со шлемом — пропуски, затем max(CPU, GPU).** Композитор SteamVR держит кадр на 11,1 мс, и
  `unscaledDeltaTime` запаса не показывает; GPU от XR-рантайма (`XRStats`) и пропущенные кадры — показывают. Без
  шлема кадр не привязан — итог по времени кадра.
- **Порядок точек** — по худшему значению оценки; направления — от худшего по оценке, чтобы прерванный замер успел
  самое важное.
- **Оставшееся время** — по формуле из спецификации на 90 кадров в секунду; без шлема редактор идёт быстрее или
  медленнее, и «осталось ~…» — оценка.

## Risks / Trade-offs

- [Скрипты игры двигают игрока (гравитация, телепорт к старту, сюжет)] → заморозка Rigidbody и CharacterController,
  выбор «Объект…»; расхождение позиции головы с точкой больше 0,5 м — пометка у точки «сдвинуто игрой».
- [Шлем лежит наклонённым — rig смотрит в пол или потолок] → в пояснении панели: положить шлем ровно; наклон головы
  в результат не пишется.
- [Оверхед редактора (Scene view, инспектор) искажает CPU] → надпись про Development Build; совет держать Game view
  в фокусе, Scene view закрытым.
- [Стриминг текстур и LOD crossfade в первые кадры после переноса] → разогрев 15 кадров, настраивается.
- [Нет шлема — моно и другой размер кадра, fill rate не тот] → пометка «без шлема» в сводке, отчёте и истории.
