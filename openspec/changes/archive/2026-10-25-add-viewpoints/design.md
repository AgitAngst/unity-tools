# Design

## Context

Аудит (`SceneAuditor.RunFullAudit`) собирает `AuditContext` один раз и считает бюджеты суммой по активным
рендерерам (`DrawCallChecks.cs`, `MeshChecks.cs`). Проходы теней на один caster уже считает
`AuditContext.ShadowPassesPerCaster`, удвоение при multi-pass — `XrInfo.DoublesDrawCalls`. История хранит файл на
набор сцен (`AuditHistory`: `SceneAuditHistory/<сцена>-<хэш>.json`). После `split-auditor-window` у окна по файлу на
вкладку. API этапа (`GeometryUtility.CalculateFrustumPlanes(Matrix4x4, Plane[])`, `TestPlanesAABB`,
`NavMesh.CalculateTriangulation`, `LODGroup.GetLODs/size/localReferencePoint`,
`QualitySettings.lodBias/maximumLODLevel`, `SceneView.duringSceneGui`, `SceneView.LookAt`, `Handles.PositionHandle`,
`PrefabUtility.GetNearestPrefabInstanceRoot`, `GlobalObjectId`) собраны пробной компиляцией против DLL 2019.4.41f2
24.10.2026.

## Goals / Non-Goals

**Goals:**
- Худшие места уровня по треугольникам, draw calls и прозрачному — за секунды, без Play Mode.
- Точки — общие для команды (файл можно коммитить), сцена не меняется.

**Non-Goals:**
- Замер в Play Mode (`add-viewpoint-tour`).
- Точный счёт батчинга, instancing, occlusion culling Unity и стоимости шейдеров.
- Terrain (владелец, 24.10.2026: «Террейн не нужен»).
- Тепловая карта всей сцены по клеткам — шарики точек её заменяют.

## Decisions

- **Точки в памяти — `ScriptableObject` с `HideFlags.DontSave`, на диске — JSON.** Перемещение, добавление и
  удаление идут через `Undo.RecordObject` — Ctrl+Z работает без своего стека; файл пишется после изменения
  (`JsonUtility.ToJson` / `FromJsonOverwrite`). Альтернатива — компонент в сцене: проще ручки, но меняет сцену и
  требует runtime-сборки, а утилита — только Editor.
- **Файл по набору сцен, как у истории.** Ключ и хэш — те же, что у `AuditHistory`, помощник один. Папка
  `SceneAuditPoints/` рядом с `SceneAuditHistory/`.
- **Расстановка по NavMesh:** для каждого треугольника `CalculateTriangulation` — узлы сетки XZ с шагом внутри его
  проекции (барицентрика даёт высоту), один узел на клетку и этаж (высота с шагом 1,5 м) → отбрасывание ближе полшага
  к уже взятой (хэш по клеткам) → +1,7 м. Больше 500 авто-точек — шаг ×1,25, пока не уложится. Телепорты — типы `Valve.VR.InteractionSystem.TeleportPoint` и `TeleportArea` через
  `ReflectionUtil`; область — та же сетка по её `bounds` с лучом вниз, попадание — в её коллайдер. Лучи вниз без
  NavMesh — по границам всех рендереров, нормаль попадания ближе 45° к вертикали.
- **Кэш рендереров один раз за оценку:** `bounds`, треугольники, слоты, отбрасывает ли тень, прозрачный ли,
  слой, группа LOD и уровень, ключ исходника (префаб → модель → сам объект), число pixel lights, задевающих
  `bounds` (от точки не зависит). Для point и spot с тенями — заранее список casters в их range. Дальше на
  направление — только проверки пирамиды; 500 × 9 × 5 000 — около 22 млн проверок `TestPlanesAABB`, порядка секунд.
- **Пирамида:** проекция `Matrix4x4.Perspective(110, 0.9, near, far)` × вид `Scale(1, 1, −1) · TRS(глаз, поворот,
  1)⁻¹` → `CalculateFrustumPlanes`. Одна на оба глаза: глаза Vive Pro смотрят почти в одну сторону, а разница в
  доли процента не стоит второго прохода. Константы — в `VRBudgets`.
- **Уровень LOD:** высота на экране = `size × max|lossyScale|` / (2 × расстояние до мировой опорной точки × tg(fov/2))
  × `lodBias`; первый уровень, чей `screenRelativeTransitionHeight` не больше её; уровни ниже `maximumLODLevel`
  пропускаются; ниже последнего перехода — группа не рисуется. Сверка с Unity — в тесте на известных расстояниях и
  вживую по полосе LODGroup в инспекторе.
- **Тени:** directional — casters, у которых `bounds.SqrDistance(глаз)` ≤ shadow distance², × каскады; point (×6) и
  spot (×1) — их casters, если куб вокруг сферы range (`Bounds` со стороной 2 × range) пересекает пирамиду. Отсечение casters каскадами не моделируется —
  оценка сверху.
- **Прозрачное:** 8 углов `bounds` → экранные координаты; угол за глазом (ближе near) или глаз внутри `bounds` —
  весь экран, 100 %. Сумма долей, обрезанных по экрану.
- **«Учитывать стены»:** `Physics.SyncTransforms`, затем лучи к центру и 4 верхним углам `bounds`
  (`RaycastNonAlloc`, без триггеров); попадание в коллайдер самого объекта или его детей не считается. Объект
  скрыт, если все 5 лучей упёрлись раньше. Лучи — на точку, а не на направление, только у объектов, видимых хоть
  в одном направлении.
- **Метки «Что здесь тяжёлое»** (константы `VRBudgets`): «далеко, а LOD0» — без LODGroup или в LOD0, меньше 5 %
  высоты экрана и больше 2 000 треугольников; «нет LODGroup» — без LODGroup и треугольников больше Warning порога
  объекта; «мелкий, но с тенью» — наибольшая сторона `bounds` меньше 0,3 м и есть в проходе теней; «крупный
  прозрачный» — прозрачный и закрывает больше 25 % экрана.
- **Вкладка второй.** Индекс вкладки в `[SerializeField] tab` сдвигается — после обновления окно откроется не на той
  вкладке один раз; это приемлемо.
- **Камера Scene view в точке:** `SceneView.LookAt(глаз + вперёд × d, поворот, size, false, false)` с `size`, при
  котором камера Scene view стоит в глазу при её текущем поле зрения; поле зрения не меняется.
- **Наборы видеокарт — таблица в `VRBudgets`** (`GpuPreset`: id `RTX2060` … `RTX3060`, имя, память карты, пороги
  треугольников и памяти текстур). Инициализаторы полей `VRBudgets` — набор RTX 3060; поле `targetGpu` (строка id)
  сохраняется в файле бюджетов. Файл проекта читается поверх инициализаторов, поэтому старый файл оставляет свои
  значения, поле прозрачного, которого в нём нет, берёт значение по умолчанию, а пустой `targetGpu` — «свои пороги».
  «Свои пороги» — не флаг, а сравнение текущих значений с набором выбранной карты: правка числа и возврат к набору
  показываются без лишнего состояния. Альтернатива — пороги как множитель от одной карты: короче, но память
  текстур зависит от объёма памяти карты, а треугольники — от скорости, одним множителем их не описать.
- **Числа наборов** — стартовые: память текстур — та же доля памяти карты, что у прежних порогов под GTX 1070
  (19 % / 25 % от 8 ГБ), треугольники — по скорости карты относительно GTX 1070. Калибровка — профайлером на
  целевом ПК, наборы правятся одной таблицей.

## Risks / Trade-offs

- [Оценка сверху расходится с Game view в разы на уровнях с батчингом и occlusion] → подпись во вкладке, замер
  этапа `add-viewpoint-tour` и сравнение «оценка ↔ замер» там.
- [Формула LOD отличается от Unity в краевых случаях (ортографические камеры, `LODGroup.animateCrossFading`)] →
  только перспектива; тест на трёх расстояниях; расхождение — запись в TESTPLAN.
- [NavMesh не запечён у части уровней] → источники выбираются галочками, лучи вниз — запасной путь, сводка
  пишет, откуда точки.
- [Лучи «стен» без коллайдеров на стенах ничего не скрывают] → режим по умолчанию выключен, подпись.
- [Большие сцены (десятки тысяч рендереров) — оценка дольше 10 с] → полоса хода с отменой, время в журнале
  `[SceneAudit] Viewpoints: N estimated, T s.`; «Оценить выбранные».
- [Сдвиг вкладок ломает снимки тестов] → `PickForShot`/`ExpandForShot` и `shoot-audit-window.ps1` обновляются в этом
  же изменении.
