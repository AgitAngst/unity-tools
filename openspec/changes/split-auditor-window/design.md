# Design

## Context

Окно — один класс `AuditorWindow : EditorWindow` на IMGUI: общие поля и стили, `OnGUI` с тулбаром и вкладками,
затем методы вкладок подряд (строки 280–727 — «Проблемы», 728–906 — «Развёртка под свет», 907–1063 — бюджеты и
допустимые, 1064–1431 — «История», 1432–1554 — «Профайлер», дальше экспорт и общие помощники). Поля всех вкладок
объявлены в начале класса и сериализуются Unity (`[SerializeField]`) — окно переживает перезагрузку домена.

## Goals / Non-Goals

**Goals:**
- Файлы до ~600 строк, по одному на вкладку, чтобы новая вкладка была новым файлом.
- Ноль изменений поведения: тот же вид, те же тексты, те же снимки.

**Non-Goals:**
- Переименования, новые классы на вкладку, перенос логики из окна, правка стилей или текстов.

## Decisions

- **`partial class`, а не класс на вкладку.** Вкладки делят поля (`result`, `picked`, стили, `budgets`) и
  помощники; отдельные классы потребовали бы передачи состояния и сменили бы сериализацию окна. `partial` —
  перенос без правки кода.
- **Поля остаются в `AuditorWindow.cs`.** `[SerializeField]`-поля одного класса в разных файлах Unity сериализует
  так же, но держать их в одном месте проще читать и сверять при следующих вкладках. Поля, которыми пользуется
  только одна вкладка, можно перенести в её файл — порядок полей на сериализацию по имени не влияет.
- **Разрез файлов:**

| Файл | Что |
|---|---|
| `AuditorWindow.cs` | константы, цвета, поля, стили, `Open`, `OnEnable`/`OnDisable`, `InitStyles`, `OnGUI`, `Run`, `AfterFix`, снимки (`PickForShot`, `ExpandForShot`), тулбар, вкладки, `SafeFixes`, раздел `shared`: экспорт и общие помощники (`XrLine`, `StereoLine`, `FormatNumber`, `SeverityColor`, `Tint`, `Padded`) |
| `AuditorWindow.Problems.cs` | вкладка «Проблемы»: пустое состояние, вывод, карточки, контекст, панель списка, полоса выбора, группы, строки, `Select` |
| `AuditorWindow.Lightmap.cs` | вкладка «Развёртка под свет» и её `Cell`, `Percent`, CSV |
| `AuditorWindow.Budgets.cs` | полосы бюджетов, вкладка «Бюджеты», допустимые проблемы, `SectionTitle`, поля порогов |
| `AuditorWindow.History.cs` | запись истории, вкладка «История» |
| `AuditorWindow.Profiler.cs` | вкладка «Профайлер» и её форматирование |
| `IssueGroup.cs` | группа проблем списка |

- **`Strings` по разделам:** `Strings.cs` — язык, `Get`, `Format`, `Add` и статический конструктор; `Strings.Ui.cs` —
  `AddUi`, тексты окна; `Strings.Checks.cs` — `AddTitles` и методы категорий, тексты проверок (`<checkId>`,
  `.title`, `.fix`, `.do`). Таблица уже заполнялась методами-разделами из одного статического конструктора — методы
  переезжают целиком, порядок заполнения прежний.
- **Перенос проверяется построчно:** каждая строка кода исходных файлов (кроме `using`, объявления класса и скобок
  вокруг) должна оказаться ровно в одном новом файле.
- **Проверка «ничего не изменилось» — снимками.** `shoot-audit-window.ps1` до разреза и после, попиксельное
  сравнение; плюс `run-audit-tests.ps1` 29 из 29.
- **Тесты и снимки — в одном открытом редакторе** (владелец, 24.10.2026: «Один раз открой и тестируй там
  постоянно»). `AuditTestServer` в тестовой сборке выполняет команды-файлы; `scripts\audit-server.ps1` открывает
  редактор один раз и переиспользует его. Тесты — в batch-редакторе: видимый на вариантах со встроенным VR сам
  добавляет пакет OpenVR и встаёт на модальных диалогах XR Plug-in Management. Снимки — в видимом; смена режима
  закрывает один редактор и открывает другой (проект открыт одним редактором за раз). Без `-nographics`:
  открытый batch-редактор крутит цикл кадров, и камеры сцены без графического устройства роняют Unity. Шаги
  `cli-*` идут через `ReportExporter.RunWithArgs` — тело `RunFromCommandLine` без выхода из редактора.

## Risks / Trade-offs

- [Статический конструктор `Strings` в одном файле, а данные — в другом] → заполнение — явными вызовами
  методов разделов, без статических полей-инициализаторов в разных файлах (их порядок между файлами не задан).
- [Новые `.cs` без `.meta`] → импорт в проверочном проекте через junction создаёт `.meta` в репозитории; коммит с ними.
- [Снимки различаются из-за времени или версии в тулбаре] → сравнивать снимки одной сборки: версия ставится
  `stamp-version.ps1` до обоих прогонов или различие в строке версии принимается при сверке.
